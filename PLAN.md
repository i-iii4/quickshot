# План работ

План реализации требований из `SYSTEM_REQUIREMENTS.md` и
`ANNOTATION_REQUIREMENTS.md`. Без оценок сроков — только объём, зависимости и
ворота приёмки. Пакет считается завершённым, когда его требования переехали в
`PRODUCT_CONTRACT.md`, покрыты headless-тестами в `scripts/test.sh` и прошли
ручную проверку на живом приложении: автоматическая зелень не считается
доказательством поведения на экране (урок из журнала — тултипы дважды
объявлялись готовыми по зелёным тестам).

Дата составления: 13.08.2026.

---

## Карта зависимостей

```
WP1 Хранение ─────────┬─→ WP5 Жизненный цикл Edited ──→ WP7 Восстановление
                      │
WP2 Прокрутка трея    │   (независим от WP1)
                      │
WP3 Каркас редактора ─┴─→ WP4 Инструменты ядра ──→ WP5
                                │
                                └─→ WP6 Приватность
                                └─→ WP8 Расширенные инструменты
```

WP1 и WP2 независимы друг от друга и от редактора — их можно вести в любом
порядке. Редактор строится цепочкой WP3 → WP4, после чего расходится на
жизненный цикл (WP5), приватность (WP6) и расширения (WP8).

---

## WP1. Хранение снимков — выполнено 13.08.2026

**Требования:** `ST-1`…`ST-12`, `ST-14`…`ST-18`. Перенесены в
`PRODUCT_CONTRACT.md`, раздел Screenshot Storage.

**Не сделано в пакете:** `ST-13` (раздельные сроки для изменённых снимков,
метка 3) — ждёт WP5, где появляется само понятие изменённого снимка.

**Состав.** Пользовательская папка сохранения с настройкой; запись файла в
момент захвата; срок жизни (день/неделя/месяц/бессрочно, умолчание неделя) с
удалением мимо корзины; уборка при запуске, периодически и при смене настройки;
выключаемое автосохранение с полным удалением материалов при закрытии трея
(`ST-5a`); развязка трея и папки (`ST-9`, `ST-10`).

**Существующий код.** `CaptureArtifact.swift` — сейчас файлы живут во временной
папке как артефакты доставки с механизмом аренд. Аренды остаются (они
обслуживают буфер и drag), добавляется второй, долговременный получатель
записи. `SettingsWindow.swift` и `hub.native` — настройки: папка, срок,
выключатель.

**Ворота.** Headless-тесты: запись при захвате, уборка по сроку с фейковыми
часами, `ST-5a` (после закрытия трея файлов нет), недоступная папка не срывает
захват (`ST-14`), уборка не трогает чужие файлы (`ST-17`). Ручная проверка:
папка появляется в Finder, файлы исчезают по сроку.

**Риск.** Гонка уборки с открытым редактором (`ST-18`) и с активной арендой
drag — уборка обязана уважать обе.

## WP2. Прокрутка трея

**Требования:** `TR-1`…`TR-17`.

**Состав.** Замена пошаговой прокрутки на непрерывную инерционную; стопки на
границах; состояние по умолчанию «стопка внизу, новое сверху»; сворачивание
продолженным жестом за границу; свайп по кнопке хаба в hidden; резиновые края;
корректность при новом снимке, смене положения трея и удалении карточки во
время жеста.

**Существующий код.** `ThumbnailManager.swift` (`scrollTray`,
`viewportScrollAccumulator`), `ThumbnailLayout.swift` (замена модели
«первый видимый индекс» на непрерывное смещение), `ThumbnailMotion.swift`
(инерция и пружины на существующих аниматорах), `NativeHubView.swift` (свайп по
кнопке). Контракт Tray And Hub пункты про append-only viewport потребуют
переписывания под новую модель.

**Ворота.** Headless: геометрия стопок для четырёх положений, порог
сворачивания (намерение против касания края), `TR-14`…`TR-16`. Ручная:
ощущение инерции неотличимо от системной прокрутки (`TR-2` проверяется только
рукой), swipe по хабу.

**Риск.** Самый большой пакет по взаимодействию с существующим кодом: прокрутка
пересекается с hover-островом, collection-транзакциями вставки и peek-показом
нового снимка. Делить на два шага: сначала непрерывная прокрутка без стопок,
потом стопки и жест сворачивания.

## WP3. Каркас редактора

**Требования:** `A-1`…`A-6`, `B-1`…`B-5`, `C-1`…`C-8`, `F-1`…`F-4`,
`G-1`…`G-10`, `H-1`…`H-5`, `J-1`…`J-5`, `L-1`…`L-5`, `M-1`…`M-3`, `N-1`,
`N-2`, `P-1`…`P-3`, `Q-1`…`Q-5`.

**Состав.** Окно редактора с холстом (зум, панорама, пиксельная чёткость);
объектная модель с undo/redo без ограничения глубины; выделение, ручки,
направляющие, клавиатура; панель инструментов-капсула по абзацу «Интерфейс»;
палитра на токенах; экспорт в буфер/файл/drag; бюджеты производительности;
крайние случаи. Интерфейс целиком на английском.

**Существующий код.** Новые файлы рядом с существующими; переиспользуются
`TrayHoverRegion` (hover панели), `HubTooltipWindow` (тултипы кнопок),
`MotionCurves`, токен-регистр Native SDK и паттерн разметки `hub.native` для
панели инструментов. `WindowCaptureProtection` — окно редактора исключается из
захвата. Вход из карточки (`A-1`) трогает `ThumbnailWindow` (двойной клик
сейчас занят копированием — конфликт решить до начала: двойной клик отдаётся
редактору, копирование остаётся на кнопке карточки и ⌘C).

**Ворота.** Headless: объектная модель и undo (приёмка `C-5`), геометрия
ручек и направляющих, клавиатурный цикл `H-1`, пиксельные пробы панели по
образцу хабовских. Ручная: первый штрих за 100 мс, отклик рисования без
пропуска кадров.

**Риск.** Undo-модель — фундамент: ошибка в ней после WP4 стоит переписывания
всех инструментов. Сначала модель с тестами, инструменты потом.

## WP4. Инструменты ядра

**Требования:** `D-1`…`D-44` (общие + стрелка, фигуры, линия, карандаш,
текст, маркер, счётчик, кадрирование), `E-1`…`E-5` (плашка и запекание).

**Состав.** Восемь инструментов ядра плюс плашка с необратимым запеканием при
экспорте. Каждый инструмент — отдельная поставка со своими тестами;
порядок внутри пакета: стрелка → прямоугольник/эллипс/линия → плашка →
текст → маркер → счётчик → карандаш → кадрирование.

**Ворота.** На инструмент: headless-тест поведения (создание, ручки,
свойства, undo) плюс пиксельная проба рендера. Для плашки — приёмка `E-2`:
в экспортированном файле под плашкой нет исходных данных ни в пикселях, ни в
метаданных. Для текста — приёмка автоконтраста на четырёх фонах (`D-27`).

## WP5. Жизненный цикл Edited

**Требования:** `ED-1`…`ED-15`, `ED-19`, `K-1`, `K-2`.
**Зависит от:** WP1, WP4.

**Состав.** Кнопка сохранения; перезапись файла; бейдж `Edited` на карточке
(Native SDK-разметка); выдача изменённой версии всеми путями (`ED-4`);
редактируемое состояние в памяти до закрытия трея (`ED-5`); поведение при
выключенном автосохранении (`ED-12`, `ED-19`).

**Ворота.** Headless: сценарий-приёмка `ED-5` (сохранить → закрыть → открыть →
объекты редактируемы → изменить → сохранить → файл обновлён), `ED-13`,
`ED-14`. Ручная: бейдж, перетаскивание отдаёт изменённую версию.

## WP6. Приватность

**Требования:** `E-6`…`E-9`.
**Зависит от:** WP4.

**Состав.** Обнаружение чувствительных данных системным OCR (почта, телефон,
карта, IP, токен, путь с именем); подсветка и закрытие одним действием без
молчаливого скрытия; режим «только текст».

**Ворота.** Headless: детектор на подготовленном наборе изображений
(совпадения и не-совпадения), «никогда молча» (`E-7`). Ручная: полный проход
сценария С-3.

## WP7. Восстановление после перезапуска

**Требования:** `ED-16`…`ED-18`, `A-8` (аварийное завершение), `K-3`.
**Зависит от:** WP5.

**Состав.** Служебная сериализация объектной модели без обязательств
совместимости: не читается — отбрасывается целиком; срок жизни привязан к
файлу снимка.

**Ворота.** Headless: восстановление после «перезапуска» (пересоздание
менеджера), повреждённое состояние отбрасывается без падения (`Q-5`-стиль),
при выключенном автосохранении не восстанавливается ничего (`ED-19`).

## Сквозные правила

1. Каждый пакет вливается только с зелёным полным `scripts/test.sh` и после
   ручной проверки на живом приложении; реализованные требования переносятся в
   `PRODUCT_CONTRACT.md` в том же изменении.
2. Бюджеты производительности (`L-*`) замеряются при первом появлении
   соответствующего пути и калибруются: числа в требованиях — ориентиры до
   первого замера.
3. Пакеты WP1 и WP2 не трогают редактор; конфликтов между ветками работ нет,
   кроме `ThumbnailWindow`/`ThumbnailManager`, которые трогают WP2, WP3 и WP5 —
   эти пакеты не вести параллельно.
4. Интерфейс всего нового — на английском (`N-1`); попутный перевод
   существующих русских строк приложения — отдельная задача вне этого плана.
